## 📌 Node.js 동작 원리 – 실생활 비유로 이해하기

---

### 1️⃣ Node.js는 왜 "싱글 스레드인데 빠르다"고 할까?

- Node.js는 **싱글 스레드** 기반이지만, **비동기 처리(Event Loop)** 구조를 활용해 동시에 많은 작업을 효율적으로 처리함
- 핵심은 **기다리지 않고 다음 일을 먼저 처리**하는 구조

---

### 2️⃣ 비유: 1인 바리스타 카페

- Node.js는 마치 혼자 일하는 **바리스타** 같다.
- 바리스타는 손님이 주문한 커피가 오래 걸리면, **다른 손님부터 먼저 응대**한다.

| 실생활 요소 | Node.js 개념 |
| --- | --- |
| 바리스타 | 싱글 스레드 |
| 예약장부 | 콜백 큐 / 마이크로태스크 큐 |
| 손님 처리 순서 조율 | 이벤트 루프 (Event Loop) |
| 커피 완성 알림 | setTimeout / Promise / async/await |

---

### 3️⃣ 실제 코드 예시

```
console.log("손님 1 도착");

setTimeout(() => {
  console.log("핸드드립 커피 준비 완료 ☕");
}, 0);

Promise.resolve().then(() => {
  console.log("빵 데우기 완료 🥐");
});

console.log("손님 2 도착");
```

🔽 출력 순서:

```
손님 1 도착
손님 2 도착
빵 데우기 완료 🥐
핸드드립 커피 준비 완료 ☕
```

---

### 4️⃣ 시각적으로 이해하기

- **Call Stack**: 바리스타가 현재 처리 중인 일
- **Callback Queue**: setTimeout처럼 뒤로 미뤄둔 작업
- **Microtask Queue**: Promise처럼 우선 처리할 짧은 작업
- **Event Loop**: 대기 중인 작업을 Call Stack에 하나씩 밀어넣는 조율자

---

### ✅ 키포인트 정리

- Node.js는 일을 미루고 예약 처리함으로써 성능을 확보함
- `Promise`, `async/await`, `setTimeout` 등은 모두 **Event Loop**와 밀접한 관련 있음
- 비동기 구조를 이해하면 **서버 개발이나 API 설계에서 실수를 줄일 수 있음**
