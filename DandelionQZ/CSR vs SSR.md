### CSR (Client-Side Rendering)

- 개념
    - CSR은 브라우저가 페이지 렌더링을 담당한다.
    - 서버는 HTML 껍데기와 자바스크립트 파일을 ‘전달’만 한다.
    - 이후 브라우저가 자바스크립트를 실행해 페이지 내용을 완성한다.
- 동작방식
    - 브라우저가 서버에서 기본 HTML + JS를 받아온다.
    - 자바스크립트가 실행되며 API로 데이터를 받아온다.
    - 데이터를 받아와서 페이지를 완성한다. (렌더링)
- 장점
    - 빠른 사용자 경험 : 페이지 간 전환 시 전체 페이지를 다시 로드하지 않아서 빠르다 (Single Page Application 구조)
    - 프론트엔드 개발자 중심 개발 : 로직이 프론트에서 돌아가기 때문에 개발 자유도가 높다.
- 단점
    - SEO(검색 엔진 최적화)에 불리 : 초기 HTML에 내용이 거의 없어서 검색 엔진이 제대로 읽고 인덱싱을 할 수가 없다.
    - 첫 화면 표시까지 시간 소요 : 자바스크립트 다운로드 → 실행 → API 호출 → 렌더링까지 시간이 걸릴 수 있다.
- 사용 사례
    - 대부분의 SPA에서 사용한다. (예: React, Vue)
    - 로그인 기반 대시보드, 내부 도구 처럼 SEO가 중요하지 않은 페이지에서 사용한다.

### SSR (Server-Side Rendering)

- 개념
    - SSR은 HTML을 ‘서버에서 완성’해서 보내는 방식이다.
    - 사용자가 요청하면 서버가 HTML을 만들어서 보내주고, 이후 자바스크립트가 동작을 활성화한다.
- 동작 방식
    - 사용자가 페이지를 요청하면 서버에서 API를 호출하고 렌더링한다.
    - 완성된 HTML을 클라이언트에 전달한다.
    - 브라우저는 받은 HTML을 바로 표시하고 자바스크립트가 추가 기능을 활성화한다.
- 장점
    - SEO에 유리 : 처음부터 내용이 있는 HTML을 제공하기 때문에 구글 같은 검색 엔진이 웹페이지의 내용을 수집해서 검색 결과에 반영할 수 있다.
    - 빠른 초기 렌더링 : 사용자에게 즉시 콘텐츠를 보여줄 수 있다.
- 단점
    - 서버 부담 증가 : 매번  HTML을 생성해야하므로 서버에 부하가 크다.
    - 복잡도 증가 : 페이지마다 데이터를 미리 불러오고, 렌더링해야 해서 개발 복잡성이 증가한다.
- 사용 사례
    - SEO가 중요한 블로그, 마케팅 페이지, 쇼핑몰 등에서 사용한다.
    - Next.js, Nuxt.js 같은 프레임워크에서 사용한다.
 
<br></br>

### 정리 및 비교

| 항목 | CSR (클라이언트 측) | SSR (서버 측) |
| --- | --- | --- |
| 초기 속도 | 느림 (JS 실행 후 렌더링) | 빠름 (HTML 바로 표시) |
| 페이지 전환 속도 | 빠름 (SPA 구조) | 보통 |
| SEO | 불리함 | 유리함 |
| 서버 부하 | 적음 | 많음 |
| 복잡도 | 낮음 | 높음 |
| 대표 프레임워크 | React, Vue (기본) | Next.js (React 기반), Nuxt (Vue 기반) |

<br></br>

### 결론

- **CSR**: 로그인 기반 앱, 대시보드, SEO가 중요하지 않은 서비스에 적합하다.
- **SSR**: 검색이 중요한 블로그, 제품 소개 페이지, 쇼핑몰, 뉴스 사이트에 적합하다.
