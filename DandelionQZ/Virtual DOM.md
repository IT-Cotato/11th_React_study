### DOM

dom은 Document Object Model의 줄임말로 HMTL문서를 분석해 페이지를 띄워주는 방식을 말한다. html 하위에는 head와 body가 있고, body의 하위에는 h1, p, div 등이 있는 것을 dom tree라고 한다. 이런 각각의 요소에 접근 가능한 방식이 getElementById 같은 API이고, 이를 통해 돔에 접근하여 요소를 수정할 수 있다.

### Virtual DOM

UI 업데이트의 효율성을 극대화하기 위해 실제돔의 복사본을 메모리 상에서 유지관리하는 기술이다. DOM 조작이 느린 브라우저 환경에서 성능을 개선하는데 중요한 역할을 한다. 배경 색 하나만 바뀌어도 돔을 새로 그려야하는데 이런 단순한 작업이라도 여러번 반복해서 수행되면 성능이 저하될 것이다. 가상돔을 활용하면 변경된 부분만 실제돔에 적용할 수 있어 문제가 해결된다. 이런 과정을 재조정(Reconciliation)이라고 하며 16ms 단위로 변경사항을 모았다가 한 번에 수행하는 batching이 있어, 데이터와 ui 업데이트가 빈번한 프로젝트에서 효율적이다.

가상돔은 javascript 객체로 구성된다. 

### 작동 방식

변경사항이 감지되면 react는 새롭게 생성한 가상돔과 이전 가상돔을 비교(diffing)하고 실제돔의 변경이 필요한 부분만 업데이트하는 패치(pathing)가 이루어진다. 

루트 노드가 다르면 해당 하위 트리를 모두 새로 렌더링한다. 리스트 요소의 경우엔 key 속성을 사용해서 추적하므로 map에서 index를 사용하는 것은 별로 좋은 방법은 아니다. key가 없으면 전체를 새로 렌더링하여 성능이 저하된다. 

### 장점

- 성능 최적화 : 돔 조작의 오버헤드 감소
- 효율적인 렌더링 : 가상돔을 생성 및 비교하더라도 메모리에서 일어나는 작업이므로 속도가 빠름
- 브라우저 호환성 : 가상돔은 브라우저 독립적이므로 여러 환경에서도 일관된 동작을 제공
- 코드 간결성 : react가 가상돔을 통해 상태 변화와 ui를 업데이트 하므로 개발자가 돔 조작을 직접 신경쓰지 않아도 됨

### 단점

- 추가적인 메모리 사용 : 실제돔과 가상돔은 별개의 메모리에 유지되기 때문에 추가적인 메모리를 사용함
- 비용이 완전히 사라지지 않음 : diffing 작업도 비용이 발생하는데 단순한 애플리에킹션에서는 성능저하가 발생할 수 있음
- 복잡한 애니메이션 구현 :  가상돔을 사용할 때 애니메이션을 구현하면 돔 변경이 지연될 수 있음
