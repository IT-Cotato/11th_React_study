## 페이지 라우팅이란?

* 경로(URL)에 따라 **알맞은 페이지를 렌더링**하는 과정.
* 사용자가 블로그 같은 웹페이지에 접속하면:

  * 브라우저가 서버에 요청을 보냄.
  * 서버는 해당 요청에 맞는 페이지를 HTML로 반환.
  * 브라우저는 이 HTML을 렌더링함.

### MPA (Multi Page Application)

* 서버가 **여러 개의 HTML 페이지**를 가지고 있음.
* 사용자가 이동할 때마다 **서버에 요청**하여 **새로운 HTML 페이지**를 받아옴.

#### 서버사이드 렌더링 (Server Side Rendering)

* 서버가 페이지를 **미리 렌더링**한 HTML로 반환하는 방식.
* 페이지 이동 시:

  * 새로운 페이지 요청 → 서버에서 해당 HTML 반환 → 기존 페이지 제거 후 새로 렌더링.
  * **깜빡거림 현상** 발생.
  * 공통 요소(헤더, 푸터 등)도 매번 다시 렌더링됨.
* 모든 요청에 서버가 반응해야 하므로:

  * **서버 부하가 큼**.
  * 사용자가 많으면 **서버 지연 또는 다운** 가능성 있음.

### SPA (Single Page Application)

* React는 SPA 방식을 따름.
* **페이지 이동이 매끄럽고 효율적**이며, 서버 부하가 적음.
* 사용자가 사이트에 접속하면:

  * 서버는 항상 `index.html`을 반환.
  * 이 HTML은 비어 있으며, 이후 React의 `bundle.js`가 로딩됨.
  * React의 `main.jsx`가 실행되어 `render()` 함수가 실행되고, 앱 컴포넌트가 브라우저에 렌더링됨.

#### 클라이언트 사이드 렌더링 (Client Side Rendering)

* 브라우저가 JS 파일을 받아서 **직접 렌더링**하는 방식.
* 페이지 이동 시:

  * **서버에 새 요청을 보내지 않음**.
  * React App 내부에서 **필요한 컴포넌트만 교체**하여 렌더링.
* 이유: React 앱 안에 **모든 페이지와 컴포넌트 정보가 저장되어 있음**.

## 동적 경로란? (Dynamic Segments)

* **동적인 데이터를 포함한 경로**를 의미함.

### 1. URL Parameter

* `/` 뒤에 **아이템의 고유 ID** 등을 명시.
* 예시:

  ```
  /product/1
  /product/2
  ```
* **변경되지 않는 값**을 주소에 명시하고자 할 때 사용.

### 2. Query String

* `?` 뒤에 변수명과 값을 명시.
* 예시:

  ```
  /search?q=keyword
  ```
* **자주 변경되는 값**을 주소에 명시하고자 할 때 사용.
