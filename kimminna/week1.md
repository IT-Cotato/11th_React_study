# [1주차] 파트 1, 2, 3 정리

# 리액트란?

리액트는 사용자 인터페이스를 만들기 위한 자바스크립트 라이브러리다.

리액트는 인터렉션이 많은 웹, 앱을 개발하기 위해 주로 사용된다.

## 프레임워크 vs 라이브러리

- 프레임워크: 어떠한 앱을 만들기 위해 필요한 대부분의 것을 가지고 있는 것
- 라이브러리: 어떠한 특정 기능을 모듈화 해 놓은 것

프레임워크는 라이브러리를 포함하고, 우리가 작성한 소스 코드를 호출한다. 그리고 소스 코드는 어떠한 기능 구현을 위해 라이브러리를 호출한다. 이렇게 프레임워크는 앱을 만드는 데 필요한 대부분의 라이브러리를 가지고 있으며, 라이브러리는 특정 기능을 위해 모듈화되어 있다.

리액트는 전적으로 UI를 렌더링하는 데 관여한다.

화면을 바꾸는 라우팅은 react-router-dom 모듈, 상태 관리를 위해선 redux, mobx 모듈 등을 사용한다. 이렇게 다른 기능을 위해서는 또다른 모듈을 사용하기 때문에 리액트는 프레임워크가 아니라 라이브러리다.

# 리액트 컴포넌트란?

리액트는 여러 컴포넌트를 이용해서 웹, 앱을 개발하게 된다.

- 컴포넌트: 리액트로 만들어진 앱을 이루는 최소한의 단위

리액트는 여러 컴포넌트 조각으로 이루어져 있다. 컴포넌트가 여러 개로 나누어져 있으면 하나의 컴포넌트를 여러 곳에서 사용할 수도 있고, 여러 명이 각자 맡은 컴포넌트를 동시에 수정할 수 있다.

## 리액트 컴포넌트의 종류

리액트 컴포넌트는 두 가지가 있는데, 클래스형 컴포넌트와 함수형 컴포넌트로 나누어진다.

간단한 예시를 들어 두 컴포넌트를 나타내면 다음과 같다.

원래 리액트를 개발할 때는 클래스 컴포넌트를 주로 사용했다고 한다. 하지만 리액트에서 훅이라는 개념을 발표한 이후부터는 함수형 컴포넌트를 주로 이용해서 개발한다.

# Node.js

리액트를 배우는 데 Node.js를 알아야 하는 이유?

Node.js는 크롬 V8 자바스크립트 엔진으로 빌드한 자바스크립트 런타임으로서, 웹 브라우저 환경이 아닌 곳에서도 자바스크립트를 사용하여 연산할 수 있다.

리액트 앱은 웹 브라우저에서 실행되는 코드여서 Node.js와 직접 연관은 없지만, 프로젝트를 개발하는 데 주요 도구들이 Node.js를 사용하기 때문에 필요하다.

이때 사용하는 개발 도구는 바벨 (Babel) , 모듈화된 코드들을 한 파일로 합치고 코드를 수정할 때마다 웹 브라우저를 리로딩하는 등 여러 기능을 지닌 웹팩 (Webpack) 이 있다.

# 브라우저가 그려지는 원리 및 Virtual DOM

리액트의 주요 특징 중 하나는 Virtual DOM을 사용한다는 것이다.

리액트가 실제 DOM 말고 Virtual DOM 을 사용하는 이유를 알아보기 전에,

DOM을 조작해서 화면을 변경할 때, 브라우저 내부에서는 어떤 과정이 일어나는지 우선 알아본다.

## 웹페이지 빌드 과정 (Critical Rendering Path)

브라우저가 서버에서 페이지에 대한 HTML 응답을 받고, 화면에 표시하기까지 여러 단계가 있다.

만약 어떤 인터렉션에 의해 DOM에 변화가 발생하면 그때마다 Render Tree가 재생성된다. 즉 모든 요소들의 스타일을 다시 계산한 뒤, Layout과 Repaint 과정까지 다시 거치는 귀찮은 과정을 겪는다. (Layout과 Repaint 과정은 매우매우 오래 걸림)

작은 변화로 인해 불필요한 과정을 계속 거치면 DOM 조작 비용이 너무 커진다.

이러한 문제로 인해 리액트에서는 Virtual DOM을 사용하는 것이다.

## Virtual DOM

가상 돔은 실제 DOM 을 메모리에 복사해 준 것으로 생각하면 된다. (자바스크립트 객체 형태로 메모리 안에 저장되어 있다.)

가상 돔은 실제 돔과 같은 모양이지만 실제 돔처럼 직접 브라우저 문서에 접근할 수는 없고, 화면에 보이는 요소를 직접 수정할 수도 없다.

리액트에서는 항상 렌더링 이전의 객체(가상 돔)과 렌더링 이후의 객체(가상 돔)을 가지고 있다. 리액트에서는 State가 바뀌면 가상 돔이 새로 생성된다. 그리고 이것을 이전에 가지고 있던 가상 돔과 비교해서 바뀐 부분만 실제 돔에 적용한다.

# Single Page Application

예전에는 웹 사이트를 만들 때 두 개 이상의 페이지를 만들기 위해 a.html과 b.html을 따로 만들곤 했었지만, 요즘에는 웹 사이트의 전체 페이지를 하나의 페이지에 담아 동적으로 화면을 바꿔가며 표현한다. 이것을 SPA 라고 한다.

전통적인 웹 사이트에서는 페이지 전환을 할 때 html을 바꿔가며 보여주면 됐지만 SPA에서는 index.html 오직 한 개만 존재한다. 여기서 동적으로 페이지를 전환하는 방법은 HTML5 의 History API를 사용해서 가능케 한다.

자바스크립트 영역에서 History API를 사용해 현재 페이지 내에서 화면 이동이 일어난 것처럼 작동하게 한다.

# JSX 문법

JSX는 자바스크립트의 확장 문법이다. 리액트에서는 이 JSX를 이용해서 화면에서 UI가 보이는 모습을 나타낸다. JSX를 쓰는 이유는 UI를 나타낼 때 자바스크립트와 HTML 구조를 같이 사용할 수 있기 때문에 기본 UI에 데이터가 변하는 것들이나 이벤트들이 처리되는 부분을 더욱 쉽게 구현할 수 있기 때문이다.

JSX를 이용하면 왜 UI를 쉽게 그릴 수 있을까?

원래 리액트에서는 `React.createElement`를 이용해서 엘리먼트를 생성한 후, `ReactDOM.render` 함수를 이용해 실제 웹 브라우저에 그려야 한다. 모든 UI를 만들 때마다 컴포넌트를 만들 수 없기 때문에, JSX를 사용한 후 그걸 바벨(Babel)이 다시 createElement로 사용해 주기 때문에 편리한 것이다.

# React State

리액트에서 데이터가 변할 때 화면을 다시 렌더링해 주기 위해서는 React State를 사용해야 한다.

State란 컴포넌트의 렌더링 결과물에 영향을 주는 데이터를 갖고 있는 객체다.

State가 변경되면 컴포넌트는 리렌더링 된다. State는 컴포넌트 안에서 관리된다.
