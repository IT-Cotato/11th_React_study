# 불필요한 setState 호출 줄이기

State를 변경하는 함수는 호출 시 비동기적으로 값이 업데이트된다. 즉, 바로 값이 반영되지 않는다. (setState를 호출하고 바로 다음 코드에 콘솔을 찍어 보면 알 수 있다.)

값이 반영되는지 확인하기 위해서는 useEffect를 통해 값이 변경될 때 콘솔을 찍어 보는 방법 등을 사용해야 한다.

이는 리액트의 최적화를 위한 방식인데, 한 번의 호출이 아닌 여러 개의 setState를 효율적으로 업데이트하기 위함이다.

# 렌더링과 커밋

리액트에서 렌더링이란, UI를 화면에 그리고, 사용자가 확인하고 상호작용하는 것을 말한다.

렌더링은 다음의 단계를 거친다.

1. 렌더링 트리거
2. 컴포넌트 렌더링
3. DOM에 커밋하기

## 1. 렌더링 트리거

### 초기 렌더링

리액트의 createRoot 앱이 시작되면 초기 렌더링이 트리거된다. 처음에는 div 태그 하나만 존재하는데, 여기에 js를 통해 UI를 넣어주게 되는 것이다. 따라서 createRoot는 DOM에서 root id를 찾고, render 메서드를 호출하여 실행된다. render 메서드를 삭제하면, UI의 구성 요소를 root div에 넣어 줄 수 없기 때문에 화면 구성 요소가 사라지게 된다.

### 상테가 업데이트되면 리렌더링

초기 렌더링 이후에는 set 함수를 사용하여 렌더링을 트리거할 수 있다. 이는 구성 요소를 업데이트하는 데 사용되며, queue에 추가된다. 여러 개의 set 함수를 추가하게 되어도 마찬가지로 queue에 쌓이게 된다.

## 2. 컴포넌트 렌더링

리액트에서 렌더링이란, 구성 요소를 호출한다는 것이다. 초기 렌더링 시에는 리액트는 루트 컴포넌트를 호출한다. (루트 컴포넌트 안에 모든 UI가 들어 있기 때문이다.)

set을 통해 렌더링을 트리거한 경우, 리액트는 트리거한 상태 업데이트의 함수 구성 요소를 호출한다. 이 과정은 재귀적으로 동작한다. 상태 업데이트의 함수 구성 요소를 호출 → 해당 함수가 또 다른 함수 반환하면 반환한 함수 호출… 이런 동작을 반복하여 렌더링하고, 더 이상 중첩된 구성 요소나 반환하는 함수가 없을 때까지 계속된다.

## 3. DOM에 커밋하기

최초 렌더링의 경우, appendChild() DOM API를 통해 생성한 모든 DOM 노드를 화면에 표시한다.

리렌더링의 경우, DOM을 최신 렌더링 화면과 일치시키기 위해 최소한의 작업을 적용한다.

## 상태로서의 스냅샷

useState를 사용하여 set 함수를 호출한 경우에는 리렌더링을 불러올 것이다. UI를 변경되려면 상태를 업데이트해야만 한다.

렌더링이란 리액트가 컴포넌트인 함수를 호출하는 것을 의미하며, 해당 함수에서 반환하는 JSX는 UI의 스냅샷과 같다. 스냅샷에는 props, 이벤트 핸들러, 로컬 변수 등이 포함되며 이러한 요소들은 컴포넌트의 상태에 따라 계산된다.

즉, 리액트는 컴포넌트를 함수처럼 호출하여, 현재 상태를 기반으로 UI를 생성하고, 사용자가 이벤트 핸들러를 통해 상호작용을 하여 입력하면, 컴포넌트를 재호출하여 새로운 상태에 맞는 UI를 생성하고 화면을 업데이트한다.

❗

리렌더링

1. 해당 컴포넌트의 함수 재호출
2. 해당 함수는 새로운 JSX 스냅샷 반환
3. 반환된 스냅샷에 맞춰서 UI 업데이트
</aside>

### 리액트에서의 상태 저장

리액트에서의 상태는 저장된다. 컴포넌트가 다시 렌더링될 때마다 리액트가 이 상태를 참조하게 된다. 컴포넌트의 생명주기에 의해 상태를 초기화하고, 이후의 렌더링 과정에서도 상태를 유지한다. 이는 언마운트될 때까지 유지되며, 언마운트되면 상태는 사라진다.

상태가 업데이트되어 UI에 반영될 때, 기존 상태값과 새로운 상태값을 비교하여 변경이 있는 부분만 업데이트하게 된다. 따라서 새로운 상태를 쉽게 관리할 수 있다.

<aside>
❗

1. 컴포넌트 초기 생성 → 상태는 초기 상태값으로 설정됨
2. 사용자가 입력을 통해 상태 변경 → set함수 호출하여 상태 업데이트 → UI 리렌더링
3. 컴포넌트 언마운트 → 해당 컴포넌트 상태의 메모리 해제
</aside>

<aside>
❗

컴포넌트가 언마운트되어도 상태를 유지하기 위해 사용하는 것이 전역 상태 관리 도구이다. 앱이 종료될 때까지 상태가 유지되며, 여러 컴포넌트에서 상태를 공유하거나 각각의 컴포넌트에서 상태에 접근할 수 있게 한다.

# 리액트의 상태 업데이트와 배치 처리

## 배치 처리란?

리액트는 상태 업데이트를 처리하기 전에 이벤트 핸들러의 모든 코드가 실행될 때까지 기다린다. 이벤트 핸들러와 그 안의 모든 코드가 완료될 때까지 UI가 업데이트되지 않음을 의미하기도 한다. 이 동작은 일부 변수만 업데이트되어 반쯤 완료된 렌더링을 처리하지 않아도 되기 때문에 앱을 더 빠르게 실행하게 해 준다.

```jsx
import { useState } from "react";

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button
        onClick={() => {
          setNumber(number + 1); // 1?
          setNumber(number + 1); // 2?
          setNumber(number + 1); // 3?
        }}
      >
        +3
      </button>
    </>
  );
}
```

setNumber는 상태값을 업데이트하는 함수인데, 동시에 여러 번 호출하더라도 현재 상태를 반영하기 때문에 세 번의 호출 모두 number의 상태값은 0이 된다. 즉, 여러 번 호출하더라도 다음 렌더링에서 반영하기 때문에 한 번의 렌더링에서만 그 변화가 반영된다.

리액트의 배치 처리로 인해 여러 상태 변경들이 하나의 렌더링으로 합쳐진다. 이는 성능 최적화를 위한 핵심 메커니즘이다.

### 동일한 상태를 여러 번 업데이트하고 싶은 경우

개발자의 의도로 상태를 여러 번 업데이트하고 싶을 경우에는 `setNumber((n)⇒n+1))` 를 사용하면 된다. 기존에 사용하던 `setNumber(number+1)` 과는 다르게, number 상태를 참조하지 않는다. 렌더링 되기 전의 고정된 상태값을 참조하는 것이 아니라 현재의 상태값을 참조하게 되는 것이다.

# 불필요한 상태 함수는 줄이기

```jsx
setNumber(number + 1);
setNumber(number + 1);
setNumber(number + 1);
```

setState(값) 방식으로 같은 상태를 여러 번 호출하면 모두 같은 이전 상태를 기준으로 처리되므로 예상하는 누적 결과가 나오지 않는다. 따라서 prevState를 이용한 함수형 업데이트 방식이 권장된다.

또한, 상태 함수를 트리거하게 되면 리렌더링이 된다. 많은 상태 함수를 호출하면 상태값 업데이트를 통해 많은 리렌더링을 불러오게 될 것이다. 그뿐만 아니라, 컴포넌트 내부에 속해 있는 자식 컴포넌트또한 업데이트되어 리렌더링이 되게 된다. 불필요한 렌더링 트리거가 성능 저하로 이어질 수 있으므로 줄이는 게 좋다.

상태 함수를 많이 사용하는 대신, useReducer, useMemo, useRef를 사용하면 대처가 가능하다.

만약 여러 개의 set 함수가 필요한 경우, 리듀서를 이용해 복잡한 상태 로직을 작성할 수 있게 된다.

또한 리액트는 렌더링 시 컴포넌트를 아예 새로 만들어서 컴포넌트 내부에 있는 함수, 변수 등을 모두 새롭게 정의하기 때문에 불필요한 메모리 소모가 일어난다. 이를 방지하기 위해 props가 변경되지 않는 한 리렌더링되지 않는 useMemo를 사용한다. (다만 실제로 useMemo를 사용할 만큼 복잡한 코드가 있는 경우는 드물기 때문에 사용하지 않는 사람도 많다고 한다.)

useRef의 경우, 상태를 업데이트하지 않기 때문에 관련 변수값은 useRef를 이용해서 저장하면 좋다.
