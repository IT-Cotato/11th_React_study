## React 상태의 분류

### 1. 관리 주체에 따른 분류

| 구분           | 설명                    | 예시                   |
| ------------ | --------------------- | -------------------- |
| Client State | 클라이언트 내부에서 생성 및 관리    | 모달 열림 여부, 입력값, 필터 상태 |
| Server State | 서버 API를 통해 받아온 외부 데이터 | 사용자 목록, 게시판 글, 알림    |

### 2. 접근 범위에 따른 분류

| 구분             | 설명                       | 예시                |
| -------------- | ------------------------ | ----------------- |
| Internal State | 컴포넌트 내부에서만 사용하는 지역 상태    | 입력값, 체크 여부        |
| External State | 여러 컴포넌트/페이지에서 공유되는 전역 상태 | 로그인 유저, 테마, 언어 설정 |

## 상태 관리 방식과 도구 비교

| 상태 유형         | 사용 Hook/도구                            | 사용 이유 및 특징                    |
| ------------- | ------------------------------------- | ----------------------------- |
| 간단한 UI 상태     | `useState`, `useReducer`              | 컴포넌트 단위 상태, 빠르고 직관적           |
| 상태 구조 복잡      | `useReducer` + `Immer`                | 불변성 유지가 어렵거나 액션 기반으로 나누고 싶을 때 |
| 전역 공유 상태 (단순) | `Context API`                         | props drilling 방지, React 내장   |
| 전역 공유 상태 (복잡) | `Redux`, `Zustand`, `Recoil`, `MobX`  | 상태 규모가 크고 여러 위치에서 접근 필요할 때    |
| 서버 상태         | `React Query`, `SWR`, `Apollo Client` | API 상태 캐싱, 동기화, 로딩/에러 관리에 최적화 |

## 대표 라이브러리별 요약

### Redux

* Flux 패턴 기반 상태 컨테이너
* 중앙 스토어에서 단방향으로 상태 관리
* 장점: 디버깅 도구 우수, 상태 추적 용이
* 단점: 보일러플레이트 많음
* 추천: 복잡한 대형 프로젝트, 협업 환경

### Zustand

* Hook 기반, Flux 패턴 간소화
* 코드가 간결하고 직관적
* Immer, devtools, persist 미들웨어 제공
* 추천: Redux보다 가볍고 빠른 대안 찾는 경우

### Context API

* React 내장 API, props drilling 방지
* Provider 하위에서 상태 전달
* 단점: 상태 변경 시 하위 전체 리렌더링 발생
* 추천: 간단한 전역 설정 (언어, 테마 등)

### Recoil

* React 전용 상태 관리
* Atom, Selector로 구성된 데이터 흐름
* 구독 기반 렌더링: 필요한 컴포넌트만 렌더링됨
* 추천: 비 Flux 스타일 선호할 때, Context 한계 넘고 싶을 때

### React Query (TanStack Query)

* 서버 상태 전용 라이브러리
* 캐싱, 자동 리패칭, 쿼리 동기화, 로딩/에러 관리 탑재
* mutation으로 데이터 생성/삭제/업데이트 가능
* 추천: 서버 데이터 중심 앱, API 연결 많은 SPA

## 선택 기준 요약표

| 상황                           | 추천 도구                  | 비고               |
| ---------------------------- | ---------------------- | ---------------- |
| 입력창 상태 관리                    | `useState`             | 가장 기본            |
| 복잡한 form, reducer 구조가 필요한 경우 | `useReducer` + `Immer` | 상태/액션 분리 가능      |
| 로그인 유저, 테마 설정 등 전역 상태        | `Context`, `Zustand`   | Context는 신중히 사용  |
| 게시판 목록, 댓글 등 API 상태          | `React Query`          | 서버 상태 캐싱 및 자동 관리 |
| 대규모 팀 프로젝트                   | `Redux`, `Zustand`     | 디버깅, 구조 명확화      |

---

### 전역 상태 사용 시 주의사항

* 모든 상태를 전역으로 올릴 필요는 없다!
* 불필요한 전역 상태는 코드 가독성 저하, 리렌더링 낭비 발생
* 상태는 항상 "누가 사용하고, 누가 변경하는가" 기준으로 판단하자

---

### 참고하면 좋은 개념들

* **불변성(immutability)**: 상태 변경 시 반드시 새 객체를 만들어야 React가 변경을 감지함
* **Prop drilling**: 중간 컴포넌트들이 사용하지 않는 props를 전달만 하는 문제
* **Single Source of Truth**: 하나의 상태가 여러 곳에서 사용될 때는 반드시 같은 출처를 공유해야 일관성 유지 가능
