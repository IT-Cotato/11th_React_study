**2.2 왜 리액트인가?**

- **React는 UI를 만들기 위한 자바스크립트 라이브러리**다.
- 웹뿐만 아니라 **React Native**를 통해 앱 개발도 가능하다.
- **SPA (Single Page Application)**
  - 하나의 페이지에서 여러 뷰를 구성해, 페이지 전체를 새로고침하지 않고 부드럽게 화면 전환 가능.
- **CSR (Client Side Rendering)**
  - 서버가 아닌 **클라이언트(브라우저)**가 렌더링을 담당해 사용자 경험(UX)을 향상시킨다.
- 컴포넌트 기반 개발로 **유지보수 용이성**, **재사용성**, **생산성**을 높여준다.

---

**2.3 라이브러리와 프레임워크의 차이**

- **프레임워크 (ex. Angular)**
  - 필요한 기능들이 **미리 정해진 틀**로 제공됨.
  - 모든 동작 방식이 규정되어 있어 **학습 난이도 높고 자율성 낮음.**
- **라이브러리 (ex. React)**
  - 특정 문제를 해결하기 위한 **작은 도구**.
  - 개발자가 필요한 기능을 **선택적으로 사용** 가능.
- React는 UI를 구성하는 데 집중된 **UI 라이브러리**이며, 뼈대를 구성한 뒤 나머지는 개발자가 자유롭게 선택 가능 (라우팅, 상태관리 등).

> 📌 React는 “라이브러리지만 프레임워크처럼 쓸 수 있다”는 유연성이 큰 장점!

---

**2.4 리액트의 철학**

- **UI = 상태(state)에 따라 변하는 결과물**
- React는 **UI를 선언적으로 그리는** 라이브러리
- 좋은 컴포넌트의 조건:
  - **독립성** (다른 컴포넌트에 영향받지 않음)
  - **고립성** (하나의 역할에 집중)
  - **재사용성** (여러 곳에서 쉽게 활용 가능)

---

**2.5 컴포넌트 나누는 기준**

- **재사용 가능한 단위**로 나눌 것
- **SRP (Single Responsibility Principle)**
- 하나의 컴포넌트는 **하나의 책임**만 가져야 함
- 너무 많은 기능을 하는 컴포넌트는 유지보수와 테스트가 어려움

---

**2.6 리액트의 동작 원리**

- 리액트는 **함수형 컴포넌트**를 권장하고 컴포넌트 이름은 **대문자**로 시작해야 함
- 컴포넌트는 JSX를 반환함 (return <div>내용</div>)
- **Props**: 부모 컴포넌트가 자식 컴포넌트에 전달하는 값
- **State**: 컴포넌트 내부에서 관리하는 데이터. 변경되면 리렌더링 발생
- 상태 변경 → 리렌더링 → **Virtual DOM**을 활용해 **변경된 부분만 실제 DOM에 반영**
- **DOM vs Virtual DOM**
  - DOM: 브라우저가 이해하는 트리 형태의 구조
  - Virtual DOM: 메모리 상에 존재하는 가상의 DOM. 효율적인 업데이트를 가능하게 함

---

**2.7 React Hooks**

- 클래스 컴포넌트의 단점:
  - 문법 복잡, this 바인딩 문제
  - 로직 재사용 어려움
- **Hooks = 함수형 컴포넌트에서 상태와 생명주기를 제어할 수 있게 해주는 기능**
  - 대표적인 Hook
  - useState: 컴포넌트의 상태 관리
  - useEffect: 컴포넌트의 생명주기 제어
- Hooks의 핵심은 **값의 재사용이 아닌, 로직의 재사용**

> 추가로 알면 좋은 Hook들

- **useContext**: 전역 상태 관리
- **useMemo, useCallback**: 성능 최적화
- **useRef**: DOM 직접 접근하거나 값 유지
  >

**3.3 기본 툴 설정**

- npm: 자바스크립트 패키지 매니저
- npx: 설치 없이 CLI 실행 가능 (ex. npx create-react-app)
- yarn: Facebook이 만든 패키지 매니저, 더 빠르고 일관된 버전 관리 가능

---

**3.6 프로젝트 구조 살펴보기**

- .yarn: yarn 관련 파일들
- public: HTML, 이미지 등 **정적 파일**
- src: 실제 코드 작성 영역
- package.json: 프로젝트 정보, 의존성, 스크립트 정의

---

**3.8 주요 개발 도구**

- **Babel**: 최신 자바스크립트 문법을 구버전으로 트랜스파일 (ex. ES6 → ES5)
- **Webpack**: 여러 파일(HTML, CSS, JS 등)을 하나로 묶어주는 번들러
- **ESLint**: 코드 문법 및 스타일 검사 도구 (팀 협업 시 필수!)
- **Jest**: 자바스크립트 테스트 프레임워크 (React에 최적화됨)
