# React에서 상태 불변성을 유지해야 하는 이유

## 불변성(immutability)이란?

불변성이란, 기존의 데이터를 직접 수정하지 않고 **복사한 후 새로운 값을 변경**하여 사용하는 방식을 말합니다. React에서는 상태(state)를 직접 변경하지 않고, 새로운 상태를 만들어 `setState` 또는 상태 업데이트 함수로 전달하는 것이 기본 원칙입니다.

## 왜 불변성을 유지해야 할까?

React는 상태의 변경을 감지하고 UI를 업데이트합니다. 그런데 React는 상태의 변경을 **객체의 참조(reference)가 변경되었는지 여부로 판단**합니다. 만약 기존 객체를 직접 수정하면 참조값은 그대로이므로 React는 변경 사항을 감지하지 못하고 렌더링도 하지 않게 됩니다.

## 잘못된 예시 (불변성 위반)

```jsx
const [user, setUser] = useState({ name: "지민", age: 20 });

// 직접 객체 수정
user.age = 21;
setUser(user); // ❌ 상태가 변경되었음을 React가 인식하지 못함
```

이 코드에서는 `user` 객체의 속성만 수정하고 다시 동일한 객체를 `setUser`에 전달하고 있습니다. 이 경우 React는 상태가 변경되지 않은 것으로 간주하고 컴포넌트를 다시 렌더링하지 않습니다.

## 올바른 예시 (불변성 유지)

```jsx
const [user, setUser] = useState({ name: "지민", age: 20 });

// 새로운 객체 생성
setUser({
  ...user,
  age: 21,
});
```

위와 같이 스프레드 연산자(`...`)를 사용해 기존 객체를 복사한 뒤 변경할 값을 덮어씌우는 방식으로 상태를 업데이트해야 합니다.

## 배열에서의 예시

```jsx
const [todos, setTodos] = useState(["공부", "청소"]);

// 새로운 항목 추가
setTodos([...todos, "운동"]); // ✅ 불변성 유지

// 기존 항목 제거
setTodos(todos.filter((todo) => todo !== "공부")); // ✅ 불변성 유지
```

`push`, `splice` 등 원본 배열을 직접 수정하는 메서드는 지양하고, `map`, `filter`, `concat` 등을 사용해 새로운 배열을 반환해야 합니다.

## 공식 문서 설명

React 공식 문서에서는 다음과 같이 강조합니다:

> "상태를 직접 수정하면 React가 변화된 것을 감지하지 못해 UI가 예상대로 동작하지 않을 수 있습니다. 항상 복사한 후 수정한 새 상태를 설정하세요."

(출처: [https://react.dev/learn/updating-objects-in-state](https://react.dev/learn/updating-objects-in-state))

## 요약

- 상태를 직접 수정하지 않고 **새로운 객체나 배열을 생성**하여 업데이트해야 합니다.
- React는 객체의 참조가 바뀌었는지로 상태 변경 여부를 판단합니다.
- 객체는 `...`, 배열은 `map`, `filter`, `concat` 등의 메서드를 활용하면 불변성을 쉽게 유지할 수 있습니다.

불변성을 지키는 습관은 React 애플리케이션의 성능 최적화뿐 아니라, **예측 가능한 버그 없는 UI** 구현에 매우 중요한 요소입니다.
