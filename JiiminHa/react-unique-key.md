# React에서 고유한 key를 사용하는 이유

## key란?

React에서 컴포넌트 목록을 렌더링할 때, 각 항목을 고유하게 식별하기 위해 `key`라는 속성을 사용합니다. 이 `key`는 React가 어떤 항목이 변경되었는지, 추가되었는지 또는 제거되었는지를 인식하는 데 중요한 역할을 합니다.

React는 리스트를 렌더링할 때 기존 DOM과의 차이를 비교하여 변경된 부분만 업데이트하는 방식으로 최적화를 수행합니다. 이 때 `key`가 없다면 각 항목이 어떤 항목인지를 추적하지 못해 불필요하게 전체 리스트를 다시 렌더링하게 됩니다.

## key의 조건

- 각 항목마다 **고유해야 하며**,
- 동일한 리스트 내에서 중복되지 않아야 합니다.

## 예시: 잘못된 key 사용

```jsx
const todos = ["공부하기", "운동하기", "청소하기"];

// 좋지 않은 방식 (index 사용)
{
  todos.map((todo, index) => <li key={index}>{todo}</li>);
}
```

위의 예시처럼 `index`를 key로 사용하는 것은 항목의 순서가 바뀌거나 중간에 요소가 삽입/삭제되는 상황에서 **React가 잘못된 항목을 업데이트**할 수 있는 가능성이 있습니다.

## 예시: 좋은 key 사용

```jsx
const todos = [
  { id: 1, text: "공부하기" },
  { id: 2, text: "운동하기" },
  { id: 3, text: "청소하기" },
];

{
  todos.map((todo) => <li key={todo.id}>{todo.text}</li>);
}
```

이처럼 고유한 `id`를 사용하는 것이 이상적입니다. 데이터베이스에서 받아온 데이터라면 보통 `id` 값이 있기 때문에 그것을 활용하면 됩니다.

## 왜 index를 key로 사용하면 안 되나?

- 리스트의 항목 순서가 바뀌면 React는 index를 기준으로 잘못된 항목을 업데이트할 수 있습니다.
- 애니메이션, 폼 입력 상태 등 리스트 항목의 상태가 중요할 때, index를 key로 사용하면 의도하지 않은 버그가 발생할 수 있습니다.

## 공식 문서에서의 설명

React 공식 문서에서는 다음과 같이 설명합니다:

> "React는 key를 통해 어떤 항목이 변경되었는지를 파악하고, 가능한 한 기존 DOM을 재사용합니다. 잘못된 key를 사용하면 React는 항목이 완전히 바뀐 것으로 간주하고 불필요하게 많은 DOM 변경을 발생시킬 수 있습니다."

## 결론

React에서 key는 리스트 항목의 식별자로 작동하며, 효율적인 리렌더링과 성능 최적화를 위해 필수적입니다. 항상 **고유한 값**을 key로 설정하고, **index는 가능하면 사용하지 않는 것**이 좋습니다.
